# Units that `lab check` is EXPECTED to fail, one path per line with a reason.
#
# Same shape and same purpose as utilities/refs_baseline.txt: the commit gate
# refuses a staged unit that does not check clean, and a unit whose whole job
# is to fail the check would make the gate unusable. A unit is in this file
# only because failing is what it is for.
#
# The gate also speaks when a unit listed here starts PASSING, because that
# means the fixture stopped being a fixture.
#
# PHASE 2c adds the second reason a unit lands here: it was SEALED before an
# enforcement existed. A sealed unit is immutable, so its prose cannot be
# brought up to a rule written after it, and the design's § A changed count
# supersedes rather than mutates does not reach the case -- that section is
# about the GENERATED layer, and a superseding unit points past a predecessor
# rather than repairing it. The line below is where a later reader finds out
# that the failure is expected and what it is.
#
# TWO RESIDUES, STATED. A baselined unit's whole `lab check` is suppressed,
# the sealed-digest verification included, so a line here is a coarser
# instrument than the finding it covers. And for a SEALED unit the gate never
# reaches this file at all: rule 2 of utilities/check_units.py refuses any
# staged change to a unit HEAD records as sealed, before any check runs. The
# line is therefore documentation first and an arming second.
