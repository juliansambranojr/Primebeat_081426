**1. Digits for counts** — new `lab/counts.py`; `lab check` prints a `DIGITS` finding with the digit form.
- before: unit whose prose says "Four runs" → `exit 0`, `0 number(s) in prose, 0 matched, 0 unmatched`
- after: `exit 1`, `DIGITS Four runs § What ran | ... -> write '4 runs'`, summary gains `1 count(s) spelled in words`

**2. 0308 sealed** — baselined in `utilities/lab_check_baseline.txt` with its reason.
- before: `check_units.baseline()` → `{'units/0000-smoke': ...}` only
- after: 0308 present with the reason; `bash utilities/hooks/pre-commit` staged → `exit 0`

**3. Nested `agents:`** — `lab/unit.py` gains one nesting: a block sequence of flat mappings, plus the formatter's inverse.
- before: `FrontMatterError: front matter line 7: key 'agents' has no value`
- after: parses to `[{'id':…, 'role':…, 'block':…}, …]`, round-trips; 8 rejection cases still refused by name (nested mapping with no `-`, second-level nesting, mismatched indent, bare scalar item, tab, …)

**4. `lab new` id** — floor read out of the frozen `notes/lab_notebook_2.md`, `max(dir id, floor)+1`. The floor comes from the notebook itself, not a constant: a constant would be a second copy of a count, and the file being frozen makes the read stable.
- before: `next_id` → `0005` in a tree whose notebook ends at 307
- after: `0308` there; `0309` in the real tree (`floor 307`, `newest sealed 0308`)

**5. Run record before the run** — index allocated and record written with `status: started`, completed afterwards with exit code, wall time, environment.
- before: 3 tests fail — no record during the run, no `status` key, `the record was never written` after a kill
- after: log of a runnable that runs `ls lab_run.*.json` shows its own record mid-run with `"status": "started"`; a SIGKILLed `lab run` leaves `status: started`, no `exit_code`, `command` and `run_start` intact

**6. `follows:`** — `lab new` writes it (newest sealed unit, omitted when none); `lab check` validates existence and self-reference only.
- before: scaffold front matter had no `follows`; `follows: 0099` → `exit 0`
- after: scaffold writes `follows: 0102`; `exit 1`, `FOLLOWS 0099 is not a unit under units`

**7. `check_refs` scans units/** — walks `units/*/unit.md` (not `question.md` or `transcript/`: those are copied-in verbatim, quoted rather than claimed), labelled by repo-relative path so the baseline stays keyed as it was; `--list-scanned` added.
- before: `--list-scanned` unsupported, no unit scanned; state line `notebook: 306 entries, newest 307 (2026-09-02), next 308`
- after: `units/0308-…/unit.md` scanned, a bad citation in a unit is a `BROKEN` line; state line `notebook: 306 entries, newest 307 (2026-09-02), FROZEN; units: 6, latest 0308, next unit 0309`. **No edit is needed under `utilities/hooks/`** — the gate already calls both scripts.

**8. A correction's evidence** — a practice, not a mechanism: `lab_design.md` § A correction reads its predecessor, plus the 2c phase row and a paragraph in `lab/check.py`.

## The two decisions

**Digits boundary: usable, implemented as a closed noun list.** The separator is the noun, never the hyphen — `four-line` is a count of lines written as an adjective and fires; `four-or-more-digit` is silent because `digit` is not a thing the archive holds. `one` is excluded (English uses it as an article; "one execution" is the design's own example). No stricter fallback needed.

**Sealed unit: baseline, not supersede.** § A changed count supersedes rather than mutates governs the *generated* layer, and a supersede points past a predecessor rather than repairing its prose — so it cannot fix 0308. The baseline is the mechanism that already exists for "expected to fail, reason written down".

## Silent or wrong in the design

- **The check_refs finding is not in 0308.** § The parser matches the spec attributes it to the unit; grep of the whole unit directory finds `check_refs` only in `question.md` and one gate line in `b01`. The finding is real, the attribution is not.
- **`follows:` cannot express the first unit's predecessor.** 0308 follows entry 307, which is not a unit — the field as specced assumes the walk lives entirely inside `units/`. That is why 0308 now reports a `FOLLOWS` finding.
- **The digits rule and the invariant pull against each other.** A count in digits is itself a number in prose and needs a `values.tsv` line. `units/0001` and `units/0003` both write "two numbers"; in digits they would fail their own check unless the run measured the count. `number` is off the noun list for that reason, and it is recorded in `lab/counts.py`.
- **"the record ... carrying the index" is unimplementable as written.** A numeric index in the record body enters the pool; it stays in the filename, as `run.py` already reasoned for `"log": "lab_run.001.log"`.
- **Baseline coarseness.** A line suppresses the whole check, digest included, and for a sealed unit the gate never reaches it — `check_units` rule 2 refuses a staged sealed unit first. Both stated in the baseline file.
- **Live hazard designed around:** `.github/workflows/audit.yml` reads `newest ([0-9]+)` off the state line and does shell arithmetic; a second `newest` carrying `0308` would hand it `$((0308 - 1))`, invalid octal. The units half says `latest`, and a test asserts the sed still yields 307.

Gates: `python3 -m pytest -q` → **244 passed**; `lab check` over all 6 units → 0000 exit 1 (its permanent job), 0001–0004 exit 0, 0308 exit 1 (baselined); pre-commit staged → exit 0; `check_refs.py` alone → exit 0.
