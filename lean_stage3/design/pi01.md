# pi01.md — RH as a Π⁰₁ sentence, built from the tree

Written 2026-11-26. Read first after any compaction; do not re-derive what is here.
No Lean was built for this note. Two scratch `#check` files were run with
`lake env lean`, and their output is quoted under Sources.

## What is wanted

A computable `pi01Check : ℕ → Bool`, built only from `ℕ` arithmetic with no `Real`
and no `Classical`, and the theorem

    theorem rh_iff_pi01 : RiemannHypothesis ↔ ∀ n : ℕ, pi01Check n = true

with `RiemannHypothesis` Mathlib's
(`Mathlib/NumberTheory/LSeries/RiemannZeta.lean:185`, opened).

**The trap the statement has to avoid.** `∃ P : ℕ → Prop, DecidablePred P ∧
(RiemannHypothesis ↔ ∀ n, P n)` takes three lines and says nothing:
`by_cases h : RiemannHypothesis`, then `P := fun _ => True` or `P := fun _ => False`,
each with an honest `Decidable` instance. So the deliverable has to be a named,
concrete `pi01Check`, and the evidence that it is decidable is that the kernel
reduces it (`decide` on small `n`). `#print axioms` does not tell you this: the
computable `Nat.lcmUpto` already prints `Classical.choice`, and `decide` still
evaluates it.

**What the theorem buys, stated exactly.** Suppose RH is false. Then some
`pi01Check n₀ = false`. That is a closed equation in `ℕ`, so Lean proves it by
kernel reduction (Σ₁-completeness), and `rh_iff_pi01` turns that proof into a
proof of `¬ RiemannHypothesis`. Taking the contrapositive: if `¬ RiemannHypothesis`
cannot be proved in Lean + Mathlib, then RH is true. In particular, if RH is
independent of Lean + Mathlib, RH is true. RH being merely unprovable does not
get you there. That is consistent with RH being false and refutable. This is a
metatheorem, written down in prose here. Lean does not state it.

## The route

One existing fact does all of the analysis: under RH, ψ satisfies a von Koch
bound with constants written as numerals. The tree already proves this
(`Stage3.psiWeak_floor_split` with `stmtEF_split_num`, `ArgCount.rvM_crude`,
`weightedZeroHeightBucket_eq_zero` and `GateEval.routeConst_le`). The converse,
with any constant, is `VonKoch.RH_of_psiWeak`. Schoenfeld's sharp constant
`1/(8π)` is never needed: the `←` direction accepts any constant and `log³`, and
the `→` direction only has to be some numeral. What remains is arithmetic: put
the real inequality between two `ℕ` inequalities.

Notation for P2–P4. `L n = Nat.lcmUpto n`, so `ψ n = log (L n)`
(`Chebyshev.psi_eq_log_lcmUpto`). Set:

- `A n = 134·(Nat.sqrt n + 1)·(Nat.log 2 n + 1)²`
- `K n = Nat.log 2 n + 4`
- `F = (K n)!`
- `a = Σ_{k<K} F/k!`

These give `(a−2)/F ≤ e ≤ (a+2)/F`.

### P2 The check — OPEN

Objects: `Nat.lcmUpto`, `Nat.sqrt`, `Nat.log`, `Nat.factorial`. All are computable,
and the kernel reduces them (`Nat.lcmUpto 10 = 2520 := by decide` ran clean).

Statement (a definition):

    def pi01Check (n : ℕ) : Bool :=
      n < 2^36 ||
        (a^n * F^(A n) ≤ L n * (a+2)^(A n) * F^n          -- e^n ≤ L·e^A, lower side
         && L n * F^(n + A n) ≤ (a+2)^(n + A n))           -- L ≤ e^(n+A), upper side

The lower side uses `a` and not `a−2` on purpose (see P3). Subtraction is avoided:
every term is a product of naturals.

The precision has to grow with `n`. A fixed rational for `e`, such as Mathlib's
`exp_one_lt_d9`, makes `(n+A)·log(hi)` exceed `n + A` by `c·n`. That is a factor
growing with the parameter, and it swallows `√n·log²n`: the design-failure case
of `CLAUDE.md`. With `K ≈ log₂ n + 4` we get `F ≥ 2^K > 8n`, and the loss is `O(1)`.

Size: 30 lines, plus `decide` examples at a few `n < 2^36` and one small `n` with
the threshold lowered in a test copy, to show the second branch reduces.

### P3 RH ⇒ check — OPEN

Statement: `RiemannHypothesis → ∀ n, pi01Check n = true`.

Route: for `n ≥ 2^36`, P1 at `x = n`:

1. `√n ≤ Nat.sqrt n + 1`, and `log n ≤ Nat.log 2 n + 1` because `log n < (Nat.log 2 n + 1)·log 2`. So `|log L − n| ≤ A`.
2. Exponentiate: `L ≤ e^(n+A)` and `e^n ≤ L·e^A`.
3. `Real.exp_bound` at `x = 1` with `n = K` gives `|e − a/F| ≤ (K+1)/(K!·K) ≤ 2/F`. So `e ≤ (a+2)/F`, which closes the upper side.
4. For the lower side, use `a/F ≤ e`. The partial sums of `e` lie below it. This is not `exp_bound`. It is a sum of nonnegative terms, roughly 10 lines (Mathlib's `Real.sum_le_exp_of_nonneg` would do it, but I have not opened that name). If that turns out to be costly, replace `a` by `a−2` in P2; then `exp_bound` alone suffices.
5. Clear denominators and cast `ℕ → ℝ`.

This direction loses nothing. Every rational bound points the safe way.

Size: 120–180 lines. Most of it is casts and `pow_le_pow_left`.

### P4 Check ⇒ RH — OPEN

Statement: `(∀ n, pi01Check n = true) → RiemannHypothesis`.

Route:

1. For `n ≥ 2^36`, the upper side gives `log L ≤ (n+A)·log((a+2)/F)`. Then `(a+2)/F ≤ e + 4/F ≤ e·(1 + 2/F)`, so `log(…) ≤ 1 + 2/F`. With `F > 8n` and `A ≤ 7n`, `ψ n − n ≤ A + 2`.
2. The lower side gives `n·log(a/F) ≤ log L + A·log((a+2)/F)`, and `log(a/F) ≥ 1 − 4/F` (from `log(1−u) ≥ −2u`). So `n − ψ n ≤ A + 2`.
3. Two arithmetic lemmas on `[2^36, ∞)` are needed: `A n ≤ 7n` and `A n + 3 ≤ 30·√n·(log n)³`. The second uses `(log₂ n + 1)² ≤ 2.3·(log n)²` once `log n ≥ 24`.
4. Pass to reals with `Chebyshev.psi_eq_psi_coe_floor`: `|ψ t − t| ≤ |ψ ⌊t⌋ − ⌊t⌋| + 1`.
5. Finish with `VonKoch.RH_of_psiWeak` (`C = 30`, `x₀ = 2^36 + 1`). Its `ChebyshevPsi` is PNT+'s `abbrev` for `Chebyshev.psi` (`MediumPNT.lean:49`, opened), so the two agree by `rfl`.

Size: 150–220 lines. This is the only block with a real inequality to fight, step 3.

### P5 The equivalence — OPEN

    theorem rh_iff_pi01 : RiemannHypothesis ↔ ∀ n : ℕ, pi01Check n = true := ⟨P3, P4⟩

Pin it with `#print axioms`, and expect `[propext, Classical.choice, Quot.sound]`.
Add a docstring carrying the metatheorem above.

Size: 15 lines.

**Total: 350–500 lines in one new module, say `Stage3/Pi01.lean`, importing
`Stage3.GateEval` and `Stage3.VonKochScaffold`. No new analysis.** The risk is in
P4 step 3, and there is a fallback: raise the threshold `2^36` or the constant 30
until `nlinarith` closes it.

**Feasibility is a separate matter from decidability.** At `n = 2^36`, `L n` has
about `10^11` bits and `(a+2)^(n+A)` about `10^13`. No instance past the threshold
will ever be evaluated. The metatheorem needs only that each instance reduces in
principle, and it does, because every operation is structural or a GMP-accelerated
`Nat` primitive.
